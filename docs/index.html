1. Install on VICIdial

Run this on your VICIdial server (as root). Pass your API key so the dialer is bound to your account. Find the key in Settings → API Keys.

curl -fsSL https://download.amdy.io/install-agi.sh | sudo bash -s YOUR_API_KEY

The installer (fully automated):

  • Checks the VICIdial environment and installs the required Perl modules
  • Downloads both AGI scripts to /var/lib/asterisk/agi-bin/ (DID selection + call-result reporter)
  • Fetches /etc/asterisk/dids.conf using your API key
  • Writes the fail-open [did-optimizer] selection context and #includes it
  • Injects the h hangup handler into [default] so results report back
  • Reloads the Asterisk dialplan and configures log rotation (30-day retention)
After install, set the fallback empty. In /etc/asterisk/dids.conf set fallback_did= (blank). On a failed lookup the script then returns nothing, and the dialplan cleanly falls back to VICIdial's own caller ID (see §3).

3. DID selection dialplan (fail-open)

The installer writes this context to /etc/asterisk/dids-dialplan.conf. It sets the caller ID only when a real DID is returned; on any failure it leaves VICIdial's caller ID untouched, so a call can never be blocked or broken.

[did-optimizer]
exten => _X.,1,NoOp(=== DID Optimizer: ${EXTEN} campaign=${campaign} ===)
exten => _X.,n,System(timeout 3 /usr/share/astguiclient/vicidial-did-optimizer-config.pl "${campaign}" "${agent}" "${EXTEN}" > /tmp/did_${UNIQUEID} 2>/dev/null)
exten => _X.,n,Set(SELECTED_DID=${FILTER(0-9+,${FILE(/tmp/did_${UNIQUEID})})})
exten => _X.,n,System(rm -f /tmp/did_${UNIQUEID})
; set caller ID ONLY on a real, non-placeholder DID; otherwise do nothing
exten => _X.,n,ExecIf($[${LEN(${SELECTED_DID})} >= 10 & "${SELECTED_DID}" != "+18005551234"]?Set(CALLERID(num)=${SELECTED_DID}))
exten => _X.,n,Goto(vicidial-auto,${EXTEN},1)

Final step (VICIdial Admin): route your campaign's outbound calls into [did-optimizer], keeping the campaign's normal Outbound Caller ID configured as the fail-open fallback.

4. Verify it's live

  1. Test connection: Settings → VICIdial Integration → Test Connection should report the VICIdial version.
  2. Sync campaigns/DIDs: the buttons should return counts > 0 (see §5 if you get 0).
  3. Place a test call on a campaign routed into [did-optimizer].
  4. Confirm the call connects normally — the DID Optimizer never blocks a call.

5. Manage DIDs & batches

Add your phone numbers in the portal under DID Management. Three ways in:

Batch identifier. Every upload can carry a Batch label (e.g. carrier-twilio-jan). The label is stored on each DID, shown as a Batch column, and available in the Batch filter — so you can view, manage, or Export Selected an entire group later. Leave it blank and one is auto-generated (BATCH-YYYY-MM-DD-NNN).

Select rows with the checkboxes and use Export Selected to download just those DIDs as CSV.

6. DID reputation checker (free)

Check whether a number is carrying spam labels before you dial it.

  • Public tool — the free checker on the site looks up any US number's RoboKiller spam status and score, no login. Limited to 5 checks per IP per day.
  • In the portal — DID Management includes an unlimited checker plus bulk reputation import, using the same engine that scores DIDs for live selection.

Statuses: Positive (clean), Neutral (usable, monitor), Negative (flagged, low answer rates), Blacklisted (auto-rested until it recovers).

7. Reduce "Spam Likely" (caller registry)

"Spam Likely" and similar tags come from the analytics providers (First Orion, Hiya, TNS) that carriers use to label calls. Registering your numbers with them reduces mislabeling.

  • The Free Caller Registry (FCR) submits your numbers to the major providers in one flow.
  • Register the numbers you actively dial from, and keep the registration current as you rotate DIDs.
  • Registration reduces mislabeling — it doesn't override a genuinely burned number. Pair it with reputation-based resting (§9) for best results.

Ask the Concierge for the current FCR steps, or contact support to have us run the submissions for you.

8. Troubleshooting

"Successfully authenticated (0 campaigns visible)" / "Synced 0 campaigns"

The API user is in the placeholder group ---ALL---, which has no campaigns. Change the user's User Group to a real group whose allowed_campaigns is -ALL-CAMPAIGNS- (usually ADMIN or MANAGERS).

"Permission denied — grant the campaigns_list permission"

Set view_reports = 1 on the API user and confirm the user's user_group also has view_reports = 1. The API checks both.

"Invalid Username / Password" from the dialer

VICIdial silently strips special characters from passwords. Re-set the password using only letters and digits, then paste the exact string into Settings → VICIdial Integration.

Calls dial but the DID never changes

The campaign isn't routed into [did-optimizer], or fallback_did is non-empty so failures return the placeholder. Confirm the routing (§3) and set fallback_did= empty.

Reinstall / repair

curl -fsSL https://download.amdy.io/install-agi.sh | sudo bash -s YOUR_API_KEY

The installer is idempotent — safe to re-run.

6. How DID selection works

For every outbound call, the optimizer scores your candidate DIDs and returns the best one:

  • ML model — a per-tenant model trained on your own call history (AMD outcomes), retrained nightly.
  • Reputation — live RoboKiller spam-label data; flagged numbers are avoided.
  • Carrier FAS — burned DIDs (carrier False-Answer-Supervision) are auto-rested.
  • Local presence — area-code / state matching to the customer where possible.

If the model is disabled or the API is unreachable, selection falls back to VICIdial's normal caller-ID logic — no call is ever blocked.
